## Source findings

The domain engine takes a snapshot, command, random source and timestamp. It returns a new snapshot with events and uses no React, timer, storage, or WebSocket imports. Both application services call this engine and the same projection functions. Bot strategy consumes only the acting seat's projection and returns an ordinary match intention. No duplicate matching, scoring, or privacy rules were found in React or the transports.

The room application owns readiness, seat authorization, and revision checks. Infrastructure parses WebSocket messages, manages connection bindings, and sends projections. The client passes typed intentions through the application-facing online contract. The composition roots supply concrete storage, randomness, the clock, and transports. Domain and application tests can exercise rules with deterministic inputs and in-memory ports. The import graph is acyclic and the boundary checks cover forbidden directions and direct clock access.

The local composition root exports a single session for the tab. Match state belongs to its injected repository. The room server owns a process-local room store. The room store deliberately returns mutable references for room metadata, so each accepted operation must complete synchronously. Moving to shared storage would require an atomic revision check and write. Domain game snapshots remain immutable. The local application surface uses its inferred type because it has one implementation, while the online session has an explicit port for its transport boundary.

## Statistics and playback data

The engine folds accepted events into bounded match counters. It counts completed turns, cards played, and actual draws, including partial penalties. Initial deals are excluded. Colored Skip, Reverse and Draw Two count under action cards. Wild and Wild Draw Four count under Wilds. Early scoring includes play and draw events already committed during an unfinished turn, while the turn itself does not count as completed. Duration is elapsed wall-clock time between deal and finish, including time spent deciding or disconnected. Rematches start fresh.

Only the public results summary is added to the existing match projection. Playback uses existing public command events and room revisions. The transport carries no animation timing or animation commands. A reconnect applies the latest snapshot without replaying missed actions. If several transitions arrive faster than playback can present them, the client can skip queued animations and catch up to the latest view.
